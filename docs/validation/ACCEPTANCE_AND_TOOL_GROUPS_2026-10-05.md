# 独立验收提速与工具分组（2026-10-05）

起因：一个只有几个文件的测试项目，说“继续”后要等约 6 分钟。拆开实际记录：真正跑测试约 20 秒；独立验收 Agent 调模型约 3.5 分钟（其中约 70 秒是它自己的测试写错后重写）；对话过长触发上下文整理约 2.4 分钟，界面没有任何提示。

## 修改

| 项 | 处理 |
| --- | --- |
| 独立验收可选 | 执行设置新增“独立验收”：自动（默认，本轮改动累计 60 行或 3 个代码文件以上才验收）/ 每次修改都验收 / 关闭。基础检查结果写明 `acceptance: required/skipped` 和原因，模型按它决定是否调用 verify_task；跳过时界面显示“检查通过，无需独立验收”。被停止的轮次留下的改动行数记在对话里，“继续”时一起算。旧版本创建的任务和旧设置文件按原行为处理 |
| 上下文整理可见 | 需要整理时先发 `CONTEXT_COMPACTING` 事件，状态行显示“整理较早的对话记录” |
| 验收 Agent 编码误判 | 提示词写明 Windows 子进程默认按 GBK 输出、`-I` 会忽略 `PYTHONIOENCODING`、要用 `-X utf8`；测试自己写错要修正重跑，不能当成环境不支持。已实测 `-I -X utf8` 输出 UTF-8 |
| 工具调用展示 | 参照 Claude Code：连续的查看目录、读取文件、搜索代码合成一行“查看了 1 个目录，读取了 2 个文件 ›”，默认收起，展开为带边框的逐条列表；验收和调查子 Agent 的步骤收进上级工具行下的分组，运行中显示当前步骤；点开一条显示状态、结果、用时、对象、错误码，原始事件折叠在最后。工具行颜色改为只作用于自身，嵌套步骤不会跟着父行变红 |
