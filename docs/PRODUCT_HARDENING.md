# 本地桌面版：本轮补齐的功能

更新日期：2026-09-09。这里只讲默认本地版本，不把旧 Redis Worker 当成默认链路。

## 先看整条线

```text
双击 Bit Agent.exe
  -> 桌面自行启动 Gateway
  -> Gateway 自行启动随包附带的 Python
  -> 选择文件夹、设置本轮权限、发送消息
  -> 恢复这段对话的历史和工作记忆
  -> 模型边回答边传文字，需要操作时申请工具
  -> 框架检查权限，再真正执行
  -> 文件修改留下前后快照，按项目语言验证
  -> SQLite 保存对话，artifacts 保存大结果和改动记录
```

Redis、PostgreSQL、系统 Node 和系统 Python 都不是便携版的启动前提。模型可以使用你配置的远程接口或本地接口；执行隔离测试仍需要 Docker。

## 1. 暂停、改目标、补要求

“暂停”不是立即冻结操作系统进程。当前模型请求或工具操作结束后，才进入安全等待位置。

- 补充要求：保留原目标，增加约束，重新考虑后续步骤。
- 修改目标：替换目标、旧约束和旧计划，但不删除已经改过的文件或已有错误记录。
- 等用户回答时释放全局执行名额，其他工作区可以继续跑。
- 同一个工作区的写入锁仍保留，避免另一个对话偷偷改掉暂停任务正在处理的代码。
- 用户等待时间不计入执行超时；恢复时用剩余时间，不重新获得完整时长。
- 关闭应用后不会保存一个活着的 Python 协程。会话和已提交要求仍在，下次续聊恢复材料，但不会自动重跑旧工具。

## 2. 工具权限不是由模型自行决定

| 界面选择 | 框架实际限制 |
| --- | --- |
| 逐次确认，默认 | 写文件、运行项目代码前，先显示具体操作并等明确批准 |
| 只读，不执行代码 | 只允许阅读、检索、提问和只读调查；拒绝写文件和运行项目代码 |
| 允许修改和隔离验证 | 普通补丁和隔离验证可以直接执行；删除文件仍要求明确确认 |

模式在创建本轮任务时确定，执行期间不能通过改下拉框偷偷改变这轮权限。

权限确认由 Python 在执行入口发起，不依赖模型自己把操作标成“低风险”。批准只对应当时的操作；补丁还会核对等待期间文件是否变化。可以展开完整操作详情。

模型的 `ask_user` 只是问问题。普通偏好可以超时采用推荐项，但它的返回值不能授权文件写入，也不能代替独立权限确认。权限确认没有超时自动批准。

## 3. 审阅和撤销

点击“审阅改动”查看本次任务真正写入的前后差异。

- “保留改动”表示接受已经存在的文件变化，不会再执行一次补丁。
- “撤销这次改动”先核对当前文件是否仍等于本次修改后的版本。不一致就拒绝覆盖。
- 同一文件改过多次，要从最新一次往前撤销。
- 任务结束且工作区没有其他执行任务时，才允许审阅操作修改文件。
- 撤销会更新对话检查点，告诉下一轮重新读取文件、重新验证，不能相信旧的补丁结果。
- 写入途中断电可能只留下“执行前快照”。这类记录不自动撤销，避免猜测磁盘状态。

记录放在应用数据目录的 `runtime/artifacts/<task_id>/changes.json`。它不是项目源码，也不是 Git 提交。快照可能包含项目代码，需要像会话记录一样保护。不要一边撤销一边在外部编辑器写同一文件；跨编辑器操作不是数据库事务。

## 4. 按项目选择验证

主 Agent 修改文件后调用 `verify_project`，路径由框架记录的改动决定，不由模型另报一份“容易通过”的范围。

| 项目 | 验证方式 |
| --- | --- |
| Python | pytest，加 Ruff 检查 |
| JavaScript / TypeScript 单包 | 按 `package.json` 执行 `test`，以及已有的 `lint`、`typecheck`、`build` |
| 找不到配置或缺少测试 | 明确返回验证失败，不能把“没有检查”显示成通过 |

前端支持 npm 和在 `packageManager` 中指定版本的 pnpm。自动依赖准备只接受公开仓库的普通包版本，不拷贝 `.npmrc`、凭证或项目源码到联网安装阶段，也不执行依赖安装脚本。

当前前端自动环境不重放锁文件；多包工作区、私有仓库、本地依赖和需要安装脚本的依赖不应当作已经支持。结果中会写明这一限制。不能把这项功能理解成“所有项目都能自动构建”。

执行测试时项目代码没有网络、工作区原件只读。前端构建产物写在容器临时副本中，不污染用户目录。取消测试会清理容器。

## 5. 流式回答和断线恢复

模型接口返回的文字片段会实时经过 Python、Gateway、Electron，到达回答区域。不是拿到完整答案后播放假打字动画。

完整答案仍在模型完成后保存，工具调用也仍等完整结果后才执行。模型流提前断掉时不自动猜测一个完整回复，也不重复执行工具。

桌面记录最后收到的 SSE 位置，断线后退避重连，并从该位置继续取事件；没有心跳也会重连。连接断开只显示连接提示，不擅自把后台任务改成失败。页面重新载入时可以从保存的事件和任务状态恢复。

## 6. 独立便携版和模型设置

开发者构建：`pnpm desktop:package`。生成一个全新的 `release/BitAgent-<时间>/` 目录。

双击目录里的 `Bit Agent.exe`，并保留整个目录一起使用。它不是可以单独拎走的一文件程序，也不是经过签名的安装包。

目录包含 Electron、Gateway、Python、Python 依赖、Git 补丁工具和 ripgrep。用户数据另存于应用数据目录，不放在发布目录里。

“模型设置”填写接口地址、模型名和 API Key。密钥经 Windows 的系统加密能力保存，页面读不到原密钥。填写新密钥才替换，留空则保留已有密钥；保存设置不等于已经实际调用模型验证连通性。

桌面管理的 Gateway 只监听本机地址，并使用每次启动生成的令牌。旧的未认证开发网关不能接收模型设置接口。

## 从哪些文件继续读

| 文件 | 大白话作用 |
| --- | --- |
| `runtime/application/service.py` | 串起任务、权限模式、存储和审阅接口 |
| `runtime/application/interaction.py` | 等待用户、处理回答和新要求 |
| `runtime/application/capacity.py` | 借出和归还执行名额 |
| `runtime/application/delegation.py` | 真正调用工具前检查权限，主 Agent 按需叫只读帮手 |
| `runtime/infrastructure/changes.py` | 前后快照、差异和有条件的撤销 |
| `runtime/infrastructure/verification.py` | 按实际项目选择检查方式 |
| `sandbox/node_environment.py` | 前端依赖的隔离准备 |
| `llm/streaming.py` | 接收模型流式文字和完整结果 |
| `apps/desktop/src/main/infrastructure/runtime/managed-runtime.ts` | 启停随包后端，加密保存模型设置 |
| `apps/desktop/src/renderer/product-controls.ts` | 权限选择、审阅和设置窗口 |
| `scripts/package-desktop.mjs` | 构建独立便携目录 |
| `scripts/accept-packaged.mjs` | 用真实 exe 和本机假模型做验收 |

表中 Python 简写路径都位于 `services/agent/src/bit_agent/`，不是根目录另一个同名文件夹。
