# 本地桌面版：本轮补齐的功能

更新日期：2026-09-09。这里讲的是本地版本（旧 Redis Worker 链路已删除）。

## 先看整条线

```text
双击 Bit Agent.exe
  -> 桌面自行启动 Gateway
  -> Gateway 自行启动随包附带的 Python
  -> 选择文件夹、设置本轮权限、发送消息
  -> 恢复这段对话的历史和工作记忆
  -> 模型边回答边传文字，需要操作时申请工具
  -> 框架检查权限，再真正执行
  -> 文件修改留下前后快照，按项目语言验证
  -> SQLite 保存对话，artifacts 保存大结果和改动记录
```

Redis、PostgreSQL、系统 Node 和系统 Python 都不是便携版的启动前提。模型可以使用你配置的远程接口或本地接口；执行隔离测试仍需要 Docker。Docker 没有运行时，输入框上方会提示：修改后的代码会显示为“无法验证”。

## 1. 暂停、改目标、补要求

“暂停”不是立即冻结操作系统进程。当前模型请求或工具操作结束后，才进入安全等待位置。

补充要求不必先暂停：运行中直接在主输入框写、按 Enter，要求先排队，Agent 在下一次调用工具或请求模型前读取；正在执行的工具不会被打断。

- 补充要求：保留原目标，增加约束，重新考虑后续步骤。
- 修改目标：替换目标、旧约束和旧计划，但不删除已经改过的文件或已有错误记录。
- 等用户回答时释放全局执行名额，其他工作区可以继续跑。
- 同一个工作区的写入锁仍保留，避免另一个对话偷偷改掉暂停任务正在处理的代码。
- 用户等待时间不计入执行超时；恢复时用剩余时间，不重新获得完整时长。
- 关闭应用后不会保存一个活着的 Python 协程。会话和已提交要求仍在，下次续聊恢复材料，但不会自动重跑旧工具。

## 2. 工具权限不是由模型自行决定

| 界面选择 | 框架实际限制 |
| --- | --- |
| 只读模式 | 只允许阅读、检索、提问和只读调查；拒绝写文件和运行检查 |
| 逐次确认，默认 | 写文件、调用外部工具前，先显示具体操作并等明确批准；隔离容器里的测试、检查和独立验收直接运行 |
| 允许修改 | 普通补丁直接写入；删除文件、修改 `.bit-agent/` 验证配置和外部工具（未标自动批准的）仍要求明确确认 |

权限在输入框下方的菜单里选（Codex 式：图标、名称和一行说明，当前项打勾），也可以在输入框里按 Shift+Tab 切换。模式在创建本轮任务时确定，执行期间不能改变这轮权限。

测试、检查和独立验收都在隔离容器里运行：不联网、不改原工作区。隔离本身就是安全边界，所以不再为它们弹确认（2026-10-04 起）。

权限确认由 Python 在执行入口发起，不依赖模型自己把操作标成“低风险”。“批准本次”只对应当时的操作；补丁还会核对等待期间文件是否变化。确认卡片直接展开差异（只留文件名，不显示 git 头信息）。

确认卡片的选项顺序和 Claude Code / Codex 一样：1 批准本次、2 本对话内都批准、3 拒绝，按数字键或点一下即提交。卡片不显示“推荐”：权限确认永不超时，推荐项不会被自动采用。

- **本对话内都批准**：这个对话里同类操作（写补丁、某个外部工具服务各算一类）不再询问，之后几轮也有效；重启应用后重新询问。删除文件和修改验证配置没有这个选项，每次都要确认。
- **拒绝并说明原因**：等确认时在主输入框写字按 Enter，等于“不批准”，你写的话会作为意见交给 Agent，让它按意见调整，而不是原样再申请。
- **拒绝运行检查**：如果检查被拒绝，任务照常结束，验证结果如实记为“未验证（你没有批准运行检查）”，不会反复催 Agent 再申请。

模型的 `ask_user` 只是问问题。普通偏好可以超时采用推荐项（默认等 5 分钟），但它的返回值不能授权文件写入，也不能代替独立权限确认。权限确认不计入每轮 20 次的提问上限，也没有超时自动批准。

## 3. 审阅和撤销

点击“审阅改动”查看本次任务真正写入的前后差异。

- “保留改动”表示接受已经存在的文件变化，不会再执行一次补丁。
- “撤销这次改动”先核对当前文件是否仍等于本次修改后的版本。不一致就拒绝覆盖。
- 同一文件改过多次，要从最新一次往前撤销。
- 任务结束且工作区没有其他执行任务时，才允许审阅操作修改文件。
- 撤销会更新对话检查点，告诉下一轮重新读取文件、重新验证，不能相信旧的补丁结果。
- 写入途中断电可能只留下“执行前快照”。这类记录不自动撤销，避免猜测磁盘状态。

记录放在应用数据目录的 `runtime/artifacts/<task_id>/changes.json`。它不是项目源码，也不是 Git 提交。快照可能包含项目代码，需要像会话记录一样保护。不要一边撤销一边在外部编辑器写同一文件；跨编辑器操作不是数据库事务。

## 4. 按项目选择验证

主 Agent 修改文件后调用 `verify_project`，路径由框架记录的改动决定，不由模型另报一份“容易通过”的范围。检查失败时与修改前的版本对比，只追究本轮新带来的问题。完整规则见 [修改后的验证](VERIFICATION.md)。

| 项目 | 验证方式 |
| --- | --- |
| Python | pytest，加只针对改动文件的 Ruff 检查 |
| JavaScript / TypeScript 单包 | 按 `package.json` 执行 `test`，以及已有的 `lint`、`typecheck`、`build` |
| 其他语言、多包项目 | 在 `.bit-agent/verify.json` 中配置命令和镜像 |
| 只改文档 | 不运行检查，结果为“无需检查” |
| 找不到配置、缺少测试或 Docker 不可用 | 结果为“无法验证”，任务可以结束，但不会显示成通过 |

前端支持 npm 和在 `packageManager` 中指定版本的 pnpm。自动依赖准备只接受公开仓库的普通包版本，不拷贝 `.npmrc`、凭证或项目源码到联网安装阶段，也不执行依赖安装脚本。

当前前端自动环境不重放锁文件；多包工作区、私有仓库、本地依赖和需要安装脚本的依赖不应当作已经支持。结果中会写明这一限制。不能把这项功能理解成“所有项目都能自动构建”。

执行测试时项目代码没有网络、工作区原件只读。前端构建产物写在容器临时副本中，不污染用户目录。取消测试会清理容器。

## 5. 流式回答和断线恢复

模型接口返回的文字片段会实时经过 Python、Gateway、Electron，到达回答区域。不是拿到完整答案后播放假打字动画。

完整答案仍在模型完成后保存，工具调用也仍等完整结果后才执行。模型流提前断掉时不自动猜测一个完整回复，也不重复执行工具。

桌面记录最后收到的 SSE 位置，断线后退避重连，并从该位置继续取事件；没有心跳也会重连。连接断开只显示连接提示，不擅自把后台任务改成失败。页面重新载入时可以从保存的事件和任务状态恢复。

## 6. 独立便携版和模型设置

开发者构建：`pnpm desktop:package`。生成一个全新的 `release/BitAgent-<时间>/` 目录。

双击目录里的 `Bit Agent.exe`，并保留整个目录一起使用。它不是可以单独拎走的一文件程序，也不是经过签名的安装包。

目录包含 Electron、Gateway、Python、Python 依赖、Git 补丁工具和 ripgrep。用户数据另存于应用数据目录，不放在发布目录里。

“模型设置”填写接口地址、模型名、接口类型和 API Key。密钥经 Windows 的系统加密能力保存，页面读不到原密钥。填写新密钥才替换，留空则保留已有密钥。

| 接口类型 | 适用服务 |
| --- | --- |
| Responses API | 支持 `/v1/responses` 的服务，例如 OpenAI 官方 |
| Chat Completions | 只提供 `/v1/chat/completions` 的兼容服务，多数国内服务商和 Ollama 等本地推理服务 |

“测试连接”用表单当前的值真实请求一次模型（带一个占位工具定义，因为任务离不开工具调用），依次尝试两种接口并选中能用的那一种；失败时分别列出每种接口的 HTTP 状态和原因。测试不会保存设置，也不改变正在使用的配置。只点“保存设置”不会发起模型请求。

连接模型服务时，建立连接最多等 20 秒，连接失败、超时、请求过多或服务端错误会自动重试 4 次（OpenAI SDK 默认只等 5 秒、重试 2 次，走代理或访问海外服务时经常不够）。可以在启动前用环境变量 `MODEL_CONNECT_TIMEOUT_SECONDS`、`MODEL_MAX_RETRIES` 调整。重试都失败时，任务结果直接说明原因，例如“连接模型服务超时，请检查网络、代理或接口地址”；网络恢复后在同一对话发送“继续”即可。

“辅助模型”是可选的：填写同一接口地址和密钥下另一个（通常更便宜的）模型名后，只读调查子 Agent、上下文摘要、长期记忆提炼和提交信息改用它；主 Agent 和独立验收仍用主模型，避免降低修改和验收质量。留空时全部使用主模型。“测试连接”只检查主模型。

Chat Completions 模式下主循环、上下文摘要和长期记忆提炼都走 `/v1/chat/completions`，并且不发送 `store`、`parallel_tool_calls` 这两个兼容服务常常不认识的参数。

桌面管理的 Gateway 只监听本机地址，并使用每次启动生成的令牌。旧的未认证开发网关不能接收模型设置接口。

## 7. 完成提醒

窗口不在前台时，下面两种情况会弹出系统通知，并让任务栏图标闪烁：

| 情况 | 通知标题 |
| --- | --- |
| 任务完成、部分完成或未完成（你自己取消的不提醒） | 任务已完成 / 任务部分完成 / 任务未完成 |
| Agent 提问，或等待你批准写文件、运行代码 | Agent 在等你回答 / 需要你确认 |

点通知回到窗口；窗口获得焦点后停止闪烁。只提醒当前打开的那段对话；断线重连时重放的旧事件（超过 1 分钟）不再提醒。便携版没有安装到开始菜单时，部分 Windows 版本可能不显示系统通知，但任务栏闪烁仍然有效。

## 8. 项目说明与 Git 提交

项目根目录的 `AGENTS.md`、`.bit-agent/instructions.md` 会在每轮任务开始时交给主 Agent；任务结束后可以在“审阅改动”里把这次任务的文件提交到 Git。详见 [项目自己的配置](PROJECT_CONFIG.md)。

## 9. 模型用量与估算费用

任务结束后，任务详情的“模型用量”显示整个任务的输入 / 输出 tokens。合计包括主 Agent、调查子 Agent、独立验收 Agent，以及上下文摘要、长期记忆提炼这类辅助请求；把鼠标停在这一行上可以看到分项和请求次数。失败或取消的任务也会记录已经花掉的用量。

在“模型设置”里填写每百万输入 / 输出 tokens 的价格后，会附上估算费用（例如 `12.3k / 2.1k · ≈¥0.04`）。价格只保存在本机、只用于显示，和服务商的实际账单可能有出入；设置了辅助模型时，它的用量也按同一价格估算，结果通常偏高。部分兼容服务在流式输出时不返回用量，这时只显示请求次数并注明“模型服务没有返回 token 用量”。

## 从哪些文件继续读

| 文件 | 大白话作用 |
| --- | --- |
| `runtime/application/service.py` | 串起任务、权限模式、存储和审阅接口 |
| `runtime/application/interaction.py` | 等待用户、处理回答和新要求 |
| `runtime/application/capacity.py` | 借出和归还执行名额 |
| `runtime/application/delegation.py` | 真正调用工具前检查权限，主 Agent 按需叫只读帮手 |
| `runtime/infrastructure/changes.py` | 前后快照、差异和有条件的撤销 |
| `runtime/infrastructure/verification.py` | 按实际项目选择检查方式 |
| `sandbox/node_environment.py` | 前端依赖的隔离准备 |
| `llm/streaming.py` | 接收模型流式文字和完整结果 |
| `apps/desktop/src/main/infrastructure/runtime/managed-runtime.ts` | 启停随包后端，加密保存模型设置 |
| `apps/desktop/src/renderer/product-controls.ts` | 权限选择、审阅和设置窗口 |
| `scripts/package-desktop.mjs` | 构建独立便携目录 |
| `scripts/accept-packaged.mjs` | 用真实 exe 和本机假模型做验收 |

表中 Python 简写路径都位于 `services/agent/src/bit_agent/`，不是根目录另一个同名文件夹。
