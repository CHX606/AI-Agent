# Agents SDK 替换验收报告

日期：2026-09-09。

## 结论

本轮完成默认 Agent 执行循环的 SDK 替换，并通过 Python 回归及真实便携 exe 的隔离联调。
不是整个系统所有模块都改成了 SDK；具体替换与保留范围见 [SDK 主线](SDK_RUNTIME.md)。

## 代码和依赖

- 使用 `openai-agents==0.22.1`；本次实际环境为 `openai==3.3.1`、`mcp==2.1.1`。
- `Agent`、`FunctionTool` 和 `Runner` 接管模型与工具循环。
- 删除旧 `services/agent/src/bit_agent/llm/streaming.py`，流式响应由 SDK 解析。
- 合并成功、失败的结果组装代码，移除运行期间重复打印工具原文的调试输出。
- 保留工作区审批、暂停补充、问题超时规则、SQLite 历史、摘要和验证要求。
- SDK 默认额外追踪上传被关闭；未引入 LangGraph 或新的后台服务。

## Python 验收

完整执行项目默认 pytest 集合：**249 passed，12 skipped**。

新增 6 项针对 SDK 接入的边界测试：

1. 模型把写文件和提问放在同一批时，只执行问题，跳过其他调用。
2. 用户修改目标后，当前批次剩余的旧工具不再执行。
3. 同一主 Agent 的工具按顺序执行，不并发写工作区。
4. 工具开始前已经保存调用计划。
5. 取消任务时等待工具清理完成，再关闭资源。
6. 重启后不盲目重放无法确认是否完成的旧写入。

旧测试里的模型回答通过测试专用 `FixtureModel` 接入；SDK Runner 本身没有被替换成假实现。
真实流式传输另外由打包 exe 对接本地 HTTP 模型验证。

`pip check` 通过。修改过的 Python 文件 Ruff lint 和格式检查通过。

第一次在受限执行环境中运行完整测试时，ripgrep 子进程和符号链接权限受阻；
在已授权的正常执行环境重新运行后通过。没有为了让测试通过而删除这些安全测试。

12 项跳过涉及 Docker 沙箱、真实 Redis/PostgreSQL、真实模型与数据库的联合测试。
本轮没有启用这些外部服务，也没有调用付费模型。

## 不在本轮结论里的内容

- 真实在线模型的生成质量、计费、延迟，以及各家 Responses 兼容端点的差异。
- Docker Engine 和沙箱镜像真实可用时的完整修复任务。
- PostgreSQL/Redis 等可选外部存储的真实连接行为。
- SDK 取代全部代码检索、摘要和业务记忆策略；这些模块没有在本轮被替换。
- 20 项布局检查不等于所有界面细节都已打磨完成，本轮没有修改前端样式。
