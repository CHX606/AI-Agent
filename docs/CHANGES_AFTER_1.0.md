# Bit Agent 1.0 之后的改动

更新时间：2026-10-04 至 2026-10-05。接在 [1.0 更新说明](RELEASE_NOTES_1.0.md)（截止提交 `efea2e6`）之后。

发布包：`release/BitAgent-2026-10-05T04-12-26-177Z/Bit Agent.exe`（整个目录一起使用）

> 前三部分已经是 3 个本地提交（`2a4d0d3`、`2b9b138`、`7a6b34b`）。独立验收提速、工具分组和两轮输出样式改动（约 40 个文件）**还没有提交**。都**没有推送**。

## 一、概览

1. **测试和检查不再需要 Docker**：改用官方 Windows OS 沙箱。复查时补上了几处隔离漏洞，并提供了系统权限加固脚本（已在本机执行）。
2. **独立验收改成可选**：默认只在改动较大时才做，小改动省下几分钟；验收 Agent 不再被中文 Windows 的编码问题误导。
3. **对话流参照 Claude Code**：查看、读取、搜索合成可展开的一行；每一行写清实际结果；去掉重复和没用的提示。
4. **界面修复**：停止更干脆、文件图标、程序图标、新对话先选工作区等。
5. **问题修复**：恢复对话时输入顺序可能颠倒、类型检查必然失败等。

## 二、测试和检查怎么运行

### 1. 从 Docker 换成官方 OS 沙箱

- 使用锁定版本 `@anthropic-ai/sandbox-runtime@0.0.78`，它的 Windows 支持由官方标为 alpha。
- 命令以独立的 `srt-sandbox` 账户运行，禁止联网（包括本机端口）。第一次运行检查时，可能弹出一次 Windows 授权，用来安装沙箱账户和网络过滤。
- 沙箱启动不了时，结果如实记为“无法验证”，不会退回成普通进程执行。
- **在哪里运行**：
  - 基础检查和独立验收在私有临时目录的工作区副本里跑，不改你的工作区。
  - 单独调用的 `run_tests`、`run_checks` 直接在工作区里跑。
- **能做什么、不能做什么**：

| 范围 | 沙箱里的命令 |
| --- | --- |
| 写入 | 只能写所在的工作区（或副本） |
| 不能改 | `.git`、`.venv`、`node_modules`、`.bit-agent`、`.codex`、`.agents`、`.claude`、`.vscode`、`.idea`、`.mcp.json`、密钥文件；根目录的 `.bit-agent` 还不存在时也不能新建 |
| 不能读 | `.env`、`.ssh`、`*.pem`、`*.key` 等密钥文件 |
| 网络 | 全部禁止 |

- 工作区的上一级目录可读：pytest 收集测试时要读它，不开放的话放在“桌面”这类私有文件夹下的项目会直接报“拒绝访问”。
- 不再构建 Docker 镜像，`.bit-agent/verify.json` 里的 `image` 字段已不支持，写了会报配置错误。

### 2. 复查时补上的隔离问题

每一项都先用真实 SDK 复现，再修复和回归。

| 问题 | 当时的表现 | 修复 |
| --- | --- | --- |
| 两个对话同时跑检查会互相写入 | 官方 SDK 的授权挂在同一个沙箱账户上，A 运行期间，B 的测试能写进 A 的工作区 | 同一时间只跑一个沙箱命令：同一程序内排队，排队时间不算进超时；执行器再加一把全机锁 |
| 测试输出能把“失败”变成“无法验证” | 测试只要打印出沙箱的错误标记文字，就会被当成沙箱没启动 | 执行器的错误标记带每次随机生成的串，被测命令拿不到 |
| 测试能绕过审批改验证配置 | 保护列表误写成 `.bit_agent`，测试写一个 `{"skip": ["**"]}` 就能让之后的改动跳过验证 | 改为保护 `.bit-agent`，目录不存在时也不能新建 |
| 类型检查必然失败 | mypy 缓存放在用户私有的临时目录，沙箱写不进去，mypy 内部出错，被报成“检查失败” | 关闭 mypy 缓存 |

### 3. 系统权限加固（已在本机执行）

- **为什么需要**：Windows 默认让所有登录用户都能修改 `D:\` 这类非系统盘，以及直接建在 `C:\` 下的文件夹。沙箱账户是普通用户，所以能改写别的项目和工具链。
- **怎么解决**：`scripts/harden-sandbox.ps1`（发布目录里也有一份）给沙箱账户所在的 `sandbox-runtime-users` 组加一条可继承的“拒绝写入”。不带参数是预览，`-Apply` 执行加固（需要管理员），`-Remove` 撤销。
- **本机已加固 8 处**：`D:\`、`E:\`、`C:\DevTools`、`C:\AMD`、`C:\DrvPath`、`C:\InstallLog`、`C:\mnt`、`C:\SteamLibrary`。加固后实测：工作区外新建、修改、删除全部被拒绝，工作区内一切正常。
- **注意**：
  - 新加的盘、在 `C:\` 下新建的文件夹，要再运行一次脚本。
  - 加固只拦写入，这些位置对沙箱仍然可读。

### 4. 审批（与 Claude Code、Codex 一致）

- **哪些模式下运行**：“逐次确认”和“允许修改”下，沙箱里的测试、检查、验收直接运行，不弹审批；“只读模式”下不运行。
- **撤销范围**：`run_tests`、`run_checks` 写出的文件不进入“审阅改动”，也不能用“撤销”还原。这和 Claude Code 的检查点不记录 Shell 改动一致，需要时用 Git 还原。

## 三、独立验收

### 1. 之前为什么要 6 分钟

一个只有几个文件的项目，说“继续”后等了约 6 分钟。按实际记录拆开看：

| 阶段 | 用时 |
| --- | --- |
| 真正跑测试 | 约 20 秒 |
| 独立验收 Agent 调模型（读代码、写测试、写报告） | 约 3.5 分钟，其中约 70 秒是它自己写错测试后重写 |
| 对话太长，先把旧记录整理成摘要（界面没有提示） | 约 2.4 分钟 |

### 2. 改成可选

“执行设置”里新增“独立验收”：

| 选项 | 行为 |
| --- | --- |
| 自动（默认） | 本轮改动累计达到 60 行，或 3 个以上代码文件（不算文档）时才验收；小改动基础检查通过就结束 |
| 每次修改都验收 | 和以前一样 |
| 关闭 | 只做基础检查 |

- 跳过时，基础检查那一行写“……，无需独立验收”，任务结果里写明原因。
- 中途被停掉的轮次改了多少行会记在对话里，下次“继续”时一起算，大改动不会因为停过就被漏掉。
- 旧版本保存的执行设置按“自动”读取；升级前创建、还没跑完的任务仍按原来的“每次都验收”。

### 3. 验收 Agent 不再误判编码问题

- **当时的问题**：它启动子进程时用了 `python -I`，这个参数会让 Python 忽略 `PYTHONIOENCODING`。中文 Windows 上子进程于是输出 GBK，测试按 UTF-8 解码失败，它却误以为是“环境捕获不到输出”，判成了“验收未完成”。
- **修复**：提示词里写明：
  - 中文 Windows 上子进程默认输出 GBK，启动 Python 子进程要加 `-X utf8`（已实测在 `-I` 下也有效）；
  - 测试是自己写错的，就修好重跑，不能当成“环境不支持”。

### 4. 整理对话记录时有提示

- 对话很长时，状态行显示“整理较早的对话记录”，不会再像卡住一样没有动静。
- 想让这一步更快，可以在“模型设置”里配一个更快的辅助模型；换话题时开新对话，也能避免整理。

## 四、界面和对话流

### 1. 工具调用分组（参照 Claude Code）

```text
● 先看一下相关代码。
● 查看了 1 个目录，读取了 3 个文件 ›
● 修改文件 src/auth/login.py
  ⎿ +12 −3
● 基础检查
  ⎿ pytest 13 个通过，ruff 无问题，无需独立验收 · 11 秒
✻ 思考中… 12 秒
```

- **合并成一行**：连续的查看目录、读取文件、搜索代码合成一行，默认收起；点开是带边框的逐条列表。
- **仍然单独一行**：修改文件、检查、独立验收、提问。
- **子 Agent 的步骤**：独立验收、调查子 Agent 的每一步，收进它上级那一行下面的分组；运行中这一行显示正在做的那一步。
- **点开一条看到什么**：状态、结果、用时、错误码，原始 JSON 收在最后的“原始事件”里。
- **颜色**：嵌套的步骤不会跟着上级行变红。

### 2. 每一行写清实际结果

| 以前 | 现在 |
| --- | --- |
| 基础检查 当前项目 ⎿ 检查通过 | 基础检查 ⎿ pytest 13 个通过，ruff 无问题；失败时写出哪条命令、几个失败；修改前就存在的失败注明“（修改前就有）” |
| 修改文件 ⎿ 修改 1 个文件 | 修改文件 ⎿ +12 −3（多个文件时“2 个文件 +12 −3”） |
| 独立验收 独立测试 Agent ⎿ 验收未完成（红色） | 独立验收 ⎿ 验收未完成：原因（琥珀色，红色只留给真正的失败） |
| 220.9s | 3 分 41 秒；短的写“6.3 秒”“11 秒” |
| 停止的轮次两行：“这一轮已停止”和“执行已停止；记录保留……” | 一行“※ 已停止” |
| 每轮都有“※ 已连接外部工具……” | 只在对话第一轮出现，连接失败时每次都提示 |
| 批准后多一行“※ 已收到你的回答” | 不再单独一行，批准与否写在对应的工具行上 |
| 状态行每次都有“· 点右下角 ■ 可停止” | 只在第一次运行时出现 |

### 3. 其他界面修复

- **停止更干脆**：点停止后立刻显示“已停止”，收起问答或暂停卡片，转圈和计时一起消失。
  - 晚到的事件不会把界面恢复成运行中。
  - 切换对话后，旧任务的事件不会写进新对话。
  - 排队的消息保留，不会自动发出。
- **文件图标**：文件树、标签页和路径导航使用 Material Icon Theme 5.39.0，1,251 个图标随包离线使用，保留原 MIT 许可。
- **标题栏**：下方的分隔线横跨整个窗口。
- **发送按钮**：第一次进入时显示灰色箭头，空输入不能发送。
- **个人中心**：去掉重复的主题切换和“已连接”文字；左侧多余的设置入口也去掉了。
- **Windows 程序图标**：橙底白色 B，10 种尺寸，任务栏图标和程序名正确，exe 改名为 `Bit Agent.exe`。
- **新对话先选工作区**：没选不能提交；已有对话固定在原来的文件夹，界面和后端都会检查。
- **代码结构**：按文件和函数长度限制，拆分了主进程入口、渲染层和样式文件，不影响功能。

## 六、行为上的变化（需要知道）

- **不再需要 Docker**：第一次运行检查时，可能要一次 Windows 授权。
- **小改动默认不做独立验收**：跳过验收的任务不会提炼长期记忆，因为记忆只从通过独立验收的任务里提炼。
- **单独运行的测试改动不进审阅**：`run_tests`、`run_checks` 写出的文件不进入“审阅改动”和“撤销”。
- **`image` 字段不再支持**：`.bit-agent/verify.json` 里写了 `image` 会报配置错误。
- **两个对话同时跑检查会排队**：同一时间只跑一个沙箱命令。
- **加固脚本要管理员身份**：新加的盘要重新运行一次。
- **对话很长时会先整理**：下一次请求前，可能要等一两分钟整理旧记录，状态行会有提示。

## 八、还需要注意

- **沙箱仍是 alpha**：官方 Windows 沙箱支持还是 alpha。放在 `AppData`、`Temp` 这类用户目录深处的 Node 项目，可能因为上级目录权限返回 EPERM。
- **基础检查可能用不到项目自己的 `.venv`（待确认）**：从代码看，基础检查运行在不含 `.venv` 的副本里，会改用 Bit Agent 自带的 Python。如果项目依赖只装在 `.venv` 里，基础检查可能报缺少依赖。这一点还没有实测。
- **只有单元测试、没有 exe 验收覆盖的部分**：基础检查的新摘要、独立验收的琥珀色和嵌套分组。验收用的假模型不会触发基础检查和独立验收，下次有真实改动时可以留意一下实际效果。
- **打包方式**：最近一次打包时连不上 pypi.org，改用本机 uv 缓存离线安装，锁定版本不变。
- **未提交部分**：独立验收提速、工具分组和输出样式改动还没提交，都没有推送。
