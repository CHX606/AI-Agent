# Bit Agent 1.0 更新说明

更新时间：2026-10-03 至 2026-10-04，共 8 个提交（`804f4de` → `efea2e6`）。68 个文件，新增约 5500 行，删除约 1250 行。

发布包：`release/BitAgent-2026-10-04T10-53-17-154Z/Bit Agent.exe`

> 所有提交都在本地 `main` 分支，**还没有推送到远程**。

## 一、概览

这一轮做了三件事：

1. **界面和交互：** 参照 Claude Code / Codex / Claude 桌面版 / VS Code 重新设计。
   - 对话按时间顺序排成一列。
   - 右下角一个主按钮完成发送、暂停和继续。
   - 权限、多 Agent、模型和思考程度用统一的弹出菜单选择。
   - 侧边栏按工作区分组，设置收进左下角的个人中心。
   - 代码仓库页改成编辑器样式。
2. **修复真实使用中卡住的问题：** 验证死循环、审批死循环、独立验收不执行、验收反复重来、模型连接超时等。
3. **版本号定为 1.0。**

## 二、界面和交互

### 1. 对话流（参照 Claude Code）

一轮对话从上到下按发生顺序排列，不再分成“你 / 执行记录 / 回答”几张卡片：

```text
› 修复登录接口的空指针
● 先看一下登录相关的代码。
● 读取文件 src/auth/login.py
  ⎿ 120 行
● 修改文件 src/auth/login.py
  ⎿ 修改 1 个文件
  （下面直接显示这次写入的差异）
● 已修复：……
✻ 思考中… 12s
```

- **工具行：** 每次调用工具显示为一行“● 动作 目标”，下一行“⎿ 结果”。圆点绿色表示成功，红色表示失败，闪烁表示运行中。点工具行可以看技术详情。
- **差异：** 修改文件后，差异直接显示在这一行下面。超过 14 行折叠，可以展开。
- **缩进和提示：** 子 Agent 调查和独立验收的工具行缩进显示；“※”开头的灰色行是流程提示。
- **状态行：** 最下面显示 Agent 正在做什么和已用时间。
- **自动滚动：** 停在底部时，新内容自动跟着滚动；往上翻看时不会被拉回去。
- **旧轮次：**
  - 继续同一对话时，上一轮的完整过程留在页面上。
  - 重新打开的对话，更早的轮次只显示回答，可以点“查看执行过程”回放。
- **段落：** 每次模型回答各自另起一段，不再粘在上一段末尾。

### 2. 输入框和主按钮（参照 Codex / Claude Code）

- **输入框高度：** 默认一行，打字时自动长高，最多约 8 行。
- **主按钮：** 右下角只有一个主按钮，图标随状态变化。

| 图标 | 什么时候 | 点击 |
| --- | --- | --- |
| ⏎ | 空闲时；运行中写了要发的文字时 | 发送 |
| 橙色弧线转圈 + 小方块 | 运行中 | 暂停（等当前这一步做完，在安全位置停下） |
| 琥珀色转圈 + 红方块 | 正在暂停，当前这一步还没做完 | 立即停止这一轮 |
| ▶ | 已暂停 | 继续执行 |

- **运行中输入文字：** 工具栏左侧出现两个选项。
  - **引导**（Enter）：立即交给正在运行的 Agent，它在下一步读到，正在执行的工具不会被打断。
  - **排队**（Tab）：这一轮结束后作为下一条消息自动发送。排队的消息显示在输入框上方，可以点 × 移除。你自己结束的那一轮之后，排队的消息不会自动发出。
- **暂停或等你回答时：** 卡片上有“继续执行”和“结束这一轮”。
- **输入框的用途随状态变化**，占位文字会提示当前能做什么：

| 状态 | 在输入框写字按 Enter |
| --- | --- |
| 空闲 | 发送新任务，或在当前对话里继续 |
| 运行中 | 引导（Tab 是排队） |
| 已暂停 | 补充要求并继续 |
| 等你批准 | 不批准，并把你写的原因交给 Agent |
| Agent 在问你 | 用你写的话回答 |

- 以前的“暂停”“停止”两个按钮和“Esc 暂停”都已去掉。

### 3. 模型和思考程度（参照 Claude Code）

- **入口：** 输入框右下角的按钮显示“模型名 · 档位”（例如 `gpt-6.1-sol 高`），点开分为“模型”和“思考程度”两组。
- **模型：** 可选主模型、辅助模型，以及模型设置里“可切换的模型”中列出的模型。
- **从服务获取：** 读取服务商的 `GET /models`，自动去掉向量、语音、图片等不能对话的模型，勾选的加进列表。
- **思考程度：** 默认、低、中、高、超高、最高，对应 OpenAI 的 `reasoning.effort`。选“默认”时不发送这个参数，由模型自己决定。Responses 和 Chat Completions 两种接口都支持。
- **生效范围：** 选择记在本机，下一条消息开始生效，重启后仍保留。只影响主 Agent。
- **不支持时：** 模型不支持所选档位时，提示“换一档或选默认”；模型名不存在时，提示换一个模型。

### 4. 权限和多 Agent 菜单（参照 Codex）

- 输入框左下角的两个下拉框改成弹出菜单：每项有图标、名称和一行说明，当前项打勾。
- **权限：** 只读模式、逐次确认、允许修改。“允许修改”用琥珀色提示风险。也可以在输入框里按 Shift+Tab 切换。
- **多 Agent：** 智能、开启、关闭。

### 5. 审批卡片

- **选项顺序：** 1 批准本次、2 本对话内都批准、3 拒绝，按数字键或点一下就提交。
- **不显示“推荐”：** 权限确认永不超时，推荐项不会被自动采用，以前推荐“拒绝”会误导。
- **内容：** 标题写明改哪个文件，例如“修改 app.py”。差异去掉 git 头信息，只留文件名。
- **等你确认时：** 正在申请的工具行显示“等待你回应…”；输入框收成一行，给卡片腾出空间。

### 6. 侧边栏和个人中心（参照 Claude 桌面版）

- **顶部：** “新对话”和“添加工作区”。
- **工作区分组：** 对话按工作区分组，每个工作区是可折叠的文件夹。
  - 标题右侧的 + 在这个工作区新开对话。
  - 添加过但还没有对话的工作区也会列出来，可以从列表移除，不会删除任何文件。
- **个人中心（左下角）：**
  - 显示本机用户名、版本号“Bit Agent 1.0”，以及本地服务的连接状态点。
  - 点开向上弹出菜单：模型设置、执行设置、外部工具、长期记忆、日志与诊断、连接设置、主题切换、版本信息。
- **去掉的旧元素：** 页面上的“Local harness v0.1”、工作区卡片和路径输入框。
- **顶部标题：** 显示对话名，不再显示最新一句话。

### 7. 代码仓库页（参照 VS Code）

- **标签页：** 打开的文件排成标签，最多 12 个，点 × 或鼠标中键关闭。
- **路径：** 显示为 `项目 › src › app.py`。
- **代码区：** 左侧固定显示行号，点击某一行会高亮这一行，状态栏显示行和列。
- **语法高亮：** 配色是 VS Code Light+ / Dark+，跟随主题；不依赖第三方库。
  - 支持 Python、JS/TS、Go、Rust、Java、C/C++/C#、JSON、YAML/TOML、HTML/XML、CSS、Markdown、Shell/PowerShell、SQL。
  - 超过 40 万字符或 8000 行的文件不着色，保证马上能打开。
- **状态栏：** 显示行数、编码、语言和文件大小。
- **资源管理器：** 每行 22px，按文件类型显示彩色图标，子目录有缩进参考线。
- **字体：** 代码改用 Cascadia Code / Consolas。以前浏览器给代码标签默认用了系统等宽字体，中文 Windows 下是新宋体，看起来像衬线字体。

### 8. 其他

- **标题栏：** 窗口标题栏由页面自己绘制，颜色跟随主题。以前暗色主题下是蓝灰色，和页面不一致。
- **Docker 提示：** 收成一行，可以关掉；Docker 状态变化时会再出现。（之后 Docker 验证整体移除，这个提示也一起去掉了。）
- **空闲时：** 不再显示红色的“停止”。

## 三、修复的问题

以下问题都在真实任务里出现过，或者用测试复现过，现在都有回归测试。

| 问题 | 当时的表现 | 修复 |
| --- | --- | --- |
| 模型连接太容易超时 | 经代理或慢网络时，连续 3 次 5 秒连接超时，任务失败 | 连接超时放宽到 20 秒、重试 4 次（可用 `MODEL_CONNECT_TIMEOUT_SECONDS`、`MODEL_MAX_RETRIES` 调整）；连不上、超时、密钥错误、额度不足时给出具体原因 |
| 验证死循环 | 基础检查“无法验证”→ 独立验收被拒绝 → 又被要求验证……一直循环 | 基础检查无法验证时，独立验收返回“无需验收”，不再翻转状态 |
| 普通 Python 文件夹不被识别 | 只有 `todo.py`、`tests/`、`requirements-dev.txt` 的项目一律“无法验证” | 有 `.py` 文件就按 Python 项目检查；没有 Ruff 配置的项目只查语法错误和明显缺陷，不套用默认风格规则 |
| 拒绝运行检查后死循环 | 照“推荐”点了拒绝，Agent 反复申请同一个检查，复现时申请了 98 次后被判失败 | 你拒绝检查后，任务照常结束，记为“未验证（你没有批准运行检查）”；被拒绝的检查不再清零提醒计数 |
| 审批时写的文字被丢掉 | 在审批卡片写“可以，但改成 b.py”，结果被当成拒绝，文字也没转给 Agent | 写字等于“不批准并说明原因”，原因会交给 Agent |
| 批准 20 次后再也写不了文件 | 审批和提问共用每轮 20 次的上限，第 21 次写入报“提问次数已达上限” | 权限确认不计入上限 |
| 独立验收的测试没跑起来 | 验收执行器只认带 `pyproject.toml` 或 `pytest.ini` 的项目，写好的 47 个用例一个都没执行 | 验收和基础检查用同一套规则识别 Python 项目 |
| 独立验收反复重来 | 验收“没能验证”被当成“还没验证”，代码没变也连续重验 3 次，每次约 3 分钟 | 验收跑了但没能得出结论时，如实收尾，显示“未完成验证”并写明原因；发现缺陷时仍要求修复 |
| 验收太慢 | 验收 Agent 写了 47 个用例，光生成就要近 2 分钟 | 改为每条需求 1–3 个关键用例，合计通常不超过 15 个，一个文件一次运行 |
| 继续对话时回答显示为空 | 最终回答要等下一帧才画出来，窗口在后台时不显示 | 任务结束时立即显示回答 |
| 代码显示成新宋体 | 仓库页的代码看起来像衬线字体 | 代码统一使用编辑器字体 |

## 四、行为上的变化（需要知道）

- **隔离环境里的检查不再弹审批：** 测试、检查和独立验收都在不联网、不改原工作区的容器里运行，“逐次确认”模式下也直接运行。需要确认的只有写文件、删除和外部工具。
  - 之后改用官方 Windows OS 沙箱：仍然禁网、仍然不弹审批（与 Claude Code、Codex 的默认做法一致），基础检查和独立验收仍在临时副本里运行；单独调用的测试和检查直接在工作区里运行，写出的文件会留在工作区，不进入改动审阅。见 [Windows OS 沙箱](ENVIRONMENT.md)。
  - 独立验收会额外调用模型、消耗 tokens。如果希望它调用前先问一句，可以改回来。
- **“本对话内都批准”：** 原来叫“本任务内都批准”，范围是一条消息；现在整个对话里都有效，重启应用后重新询问。
- **提问等待时间：** Agent 普通提问的默认等待从 60 秒改为 5 分钟，超时才采用推荐项。
- **运行中可以直接补充要求：** 不用先暂停。
- **Esc 不再暂停：** 只用来关闭菜单；暂停用右下角的主按钮。
- **版本号：** 1.0，取自 `apps/desktop/package.json`。

| 按键 | 作用 |
| --- | --- |
| Enter | 发送；运行中是“引导”；等回答时是“回答”（输入法选词时的回车不会发送） |

| Tab | 运行中写了文字时：排队，这一轮结束后自动发送 |

## 六、验证情况

- **单元和集成测试：** Python 561 个通过；桌面端 69 个、网关 32 个通过；类型检查和分层规则检查通过。
- **打包验收：** 用 `scripts/accept-packaged.mjs` 启动真正的 exe，配一个本地假模型，从头到尾操作界面并检查结果。本轮新增的检查项：
  - 运行中引导、按 Tab 排队后自动发送、继续对话后上一轮过程仍在；
  - 主按钮的三种状态和“立即停止”、“结束这一轮”；
  - 权限菜单、审批选项顺序、旧轮次回放；
  - 从服务获取模型、所选模型和思考程度重启后仍出现在模型请求里；
  - 仓库页的标签页、行号、高亮、等宽字体；
  - 侧边栏分组、个人中心、版本号 1.0。

## 七、还需要确认或注意的

- **还没用真实模型从头到尾跑过：** 打包验收用的是本地假模型。思考程度在你的服务商（`gpt-6.1-sol`）上支持哪些档位，需要实际发一次任务确认。
- **Docker：** 隔离测试需要 Docker。没开时，改动只能标为“无法验证”。（之后改为随包的官方 Windows OS 沙箱，不再需要 Docker。）
- **标题栏：** 自绘标题栏依赖 Windows 的标题栏叠加功能；其他系统没有测试过。
- **还没推送：** 所有改动都在本地 `main` 分支。
