# Desktop 和 CLI：怎样使用这个项目

更新日期：2026-10-03。

Desktop 是桌面窗口，CLI 是终端命令。默认任务经过 Gateway 和本地 Python 运行库，不再需要 Redis。
桌面支持会话恢复和关闭／开启／智能三档模式；旧 CLI 命令不等于完整的桌面多轮会话界面。

Desktop 另外提供本地仓库浏览和文本预览，用来帮助你理解选中的项目。

## 先准备后台

先安装项目依赖并配置聊天模型。`pnpm desktop:dev` 会启动本地后台和桌面；使用隔离测试工具时仍需 Docker。具体顺序见 [本地运行说明](LOCAL_RUNTIME.md)。

默认 Gateway 地址为 `http://127.0.0.1:3000`。普通任务不强制要求 Ollama；配置向量记忆时才需要相应向量服务。

## Desktop 怎样启动

首次安装 Node.js 依赖：

```powershell
pnpm install
```

构建并打开 Electron 窗口：

```powershell
pnpm desktop:dev
```

当前这条命令先构建，再启动 Gateway、本地 Python 执行进程和 Electron。
如果已另行启动 Gateway，请用 `pnpm desktop:only`，避免占用同一端口。

只构建时使用：

```powershell
pnpm desktop:build
```

构建后的代码在 `apps/desktop/dist`。要修改界面，应修改 `src` 中的源码；再次构建会重新生成 `dist`。

## 界面里能做什么

- 选择本地工作区，输入自然语言任务。
- 提交、查询和取消任务。
- 查看工具执行事件、修改文件、测试与检查结果、最终回答。
- 浏览选中仓库的目录和文本文件。
- 审阅改动、撤销，或把这次任务的文件提交到 Git。
- 窗口在后台时，任务结束或等待回答会弹出系统通知。
- 切换主题，保留部分本地界面偏好和任务历史信息。

## 侧边栏和个人中心（参照 Claude 桌面版）

- **顶部：** “新对话”和“添加工作区”。添加工作区就是选一个本地代码仓库。
- **工作区分组：** 对话按工作区分组，每个工作区是一个可以折叠的文件夹。
  - 标题右侧的 + 在这个工作区新开对话。
  - 当前工作区排在最上面，其余按最近的对话排序。
  - 添加过但还没有对话的工作区也会列出来；悬停时可以点 × 从列表移除，不会删除任何文件。
  - 搜索对话时只显示有匹配的工作区。
- **个人中心（左下角）：** 显示本机用户名和版本号（Bit Agent 1.0），旁边的小圆点表示本地服务的连接状态。点开向上弹出菜单：
  - 模型设置、执行设置、外部工具、长期记忆、日志与诊断、连接设置；
  - 切换浅色或暗色主题；
  - 版本信息。

## 对话界面（参照 Claude Code）

一轮对话从上到下按发生顺序排列，不再分成“你 / 执行记录 / 回答”几张卡片：

```text
› 修复登录接口的空指针
● 先看一下登录相关的代码。
● 读取文件 src/auth/login.py
  ⎿ 120 行
● 修改文件 src/auth/login.py
  ⎿ 修改 1 个文件
  （下面直接显示这次写入的差异，超过 14 行可展开）
● 已修复：……
✻ 思考中… 12s · Esc 暂停
```

- 圆点颜色表示结果：绿色成功，红色失败，闪烁表示运行中。点工具行可以看技术详情。
- 子 Agent 的调查和独立验收缩进显示；“※”开头的灰色行是流程提示，比如读取了 AGENTS.md。
- 最下面的状态行显示 Agent 正在做什么和已用时间。往上翻看时不会被新内容拉回底部，回到底部后继续跟随。
- 继续同一对话时，上一轮的完整过程留在页面上。重新打开的对话里，更早的轮次只显示回答，点“查看执行过程”回放那一轮。

| 按键 | 作用 |
| --- | --- |
| Enter | 发送（输入法选词时的回车不会发送） |
| Shift+Enter | 换行 |
| Shift+Tab | 依次切换权限：逐次确认 → 允许修改 → 只读模式 |
| Esc | 运行中暂停；菜单打开时只关闭菜单 |
| 数字键 1–3 | 在问答或审批卡片里直接选择对应选项并提交（光标在空的输入框里也可以） |

主输入框随任务状态换用途，占位文字会提示当前能做什么：

| 状态 | 在输入框写字按 Enter |
| --- | --- |
| 空闲 | 发送新任务，或在当前对话里继续 |
| 运行中 | 补充要求：先排队，Agent 下一步读取，不打断正在执行的工具 |
| 已暂停 | 补充要求并继续 |
| 等你批准 | 不批准，并把你写的原因交给 Agent |
| Agent 在问你 | 用你写的话回答 |

你写的话会以“›”显示在过程里。修改原目标（替换目标和计划）在卡片的“修改目标”里。

输入框默认只有一行，打字时自动长高（最多约 8 行）。

输入框右下角是“模型 · 思考程度”按钮（参照 Claude Code），可以临时换模型和思考档位，详见 [功能说明](PRODUCT_HARDENING.md)。

输入框左下角有两个菜单，样式参照 Codex：每项有图标、名称和一行说明，当前项打勾。

- **权限：** 只读模式、逐次确认、允许修改，具体限制见 [功能说明](PRODUCT_HARDENING.md)。
- **多 Agent：** 智能、开启、关闭。

Docker 没开时，输入框上方会有一行提示，可以关掉；Docker 状态变化时会再出现。

普通寒暄会直接回答，不会因为已经选择工作区就启动仓库扫描。只有明确的代码任务才会
创建子 Agent 并运行仓库验证；直接回复的 Docker 与 Ruff 状态显示为“未运行”，不是“未通过”。

## 代码仓库页（参照 VS Code）

左侧栏的文件夹图标打开仓库页：

- **资源管理器：** 每行 22px，目录有展开箭头和文件夹图标，文件按类型显示彩色小图标（py、TS、JS、{}、M↓ 等），子目录有缩进参考线。
- **编辑区：**
  - 打开的文件排成标签页，最多 12 个；点 × 或鼠标中键关闭。
  - 上方显示路径，例如 `项目 › src › app.py`。
  - 代码带行号和语法高亮，配色是 VS Code 的 Light+ / Dark+，跟随应用主题。
  - 点某一行会高亮这一行，底部状态栏显示行和列。
- **状态栏：** 显示行数、编码、语言和文件大小。
- **语法高亮：** 支持 Python、JS/TS、Go、Rust、Java、C/C++/C#、JSON、YAML/TOML、HTML/XML、CSS、Markdown、Shell/PowerShell、SQL；其他文件按纯文本显示。超过 40 万字符或 8000 行的文件不着色，保证马上能打开。
- 仓库页只读，不能在这里修改文件。

目录预览用于查看文件。任务历史用于找回任务编号和展示信息，不等于 Gateway 返回的完整任务结果，也不等于已经做了源码备份。

桌面端主进程负责文件对话框、受控目录读取和 Gateway 请求。页面进程通过 preload 提供的接口调用这些能力。

## CLI 怎样启动

安装 Python 项目后会生成 `bit-agent` 命令。如果没有激活虚拟环境，可以直接使用完整的项目内入口：

```powershell
./.venv/Scripts/bit-agent.exe run --workspace "D:/path/to/repo" --task "定位失败测试并修复"
```

已经激活项目虚拟环境时，可以简写：

```powershell
bit-agent run --workspace "D:/path/to/repo" --task "定位失败测试并修复"
```

## 常用命令

| 命令 | 大白话解释 |
| --- | --- |
| `bit-agent run --workspace "D:/repo" --task "修复问题"` | 提交任务，并继续等待事件和结果。 |
| `bit-agent run --workspace "D:/repo" --task "修复问题" --detach` | 提交后返回，不一直占着终端等待。 |
| `bit-agent status TASK_ID` | 查询指定任务进行到哪里。 |
| `bit-agent result TASK_ID --json` | 获取结构化结果，适合排查问题或供程序读取。 |
| `bit-agent cancel TASK_ID` | 请求停止指定任务。 |

`TASK_ID` 是提交任务时返回的编号，不是让你原样输入这几个字母。

使用 `--gateway` 或环境变量 `BIT_AGENT_GATEWAY_URL` 可以指定 Gateway 地址，例如：

```powershell
bit-agent status TASK_ID --gateway "http://127.0.0.1:3000"
```

## 先用哪个示例理解

`workspaces/desktop-demo-calculator` 是桌面演示工作区。当前加法实现已经是正常相加，旧 README 中的“存在错误”已更新，不能假设它仍是一道未修复的题。

`evals/fixtures` 和 `services/agent/evals/fixtures` 则保存评测题目。重新做题应使用隔离副本，避免把原始题目改成答案。

## 对应代码

- `apps/desktop/src/main`：Electron 主进程和本地文件访问。
- `apps/desktop/src/renderer`：界面、事件展示、文本和 Markdown 呈现。
- `apps/desktop/src/shared`：界面和主进程之间的数据约定。
- `services/agent/src/bit_agent/cli.py`：命令行入口。
- `services/agent/src/bit_agent/client`：Python Gateway 客户端。

Desktop 的页面进程没有直接开放 Node.js 能力；本机 Gateway 可以使用 HTTP，远程地址需要 HTTPS。具体地址规则和访问限制由客户端代码执行。
