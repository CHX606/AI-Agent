# 项目自己的配置：说明文件、验证命令、Git 提交和对话管理

更新日期：2026-10-01。本文说明你可以在自己的项目里放哪些文件来影响 Bit Agent、任务结束后怎样把改动提交到 Git，以及怎样搜索、重命名和删除对话。

## 项目说明文件

在项目根目录放以下任意文件，每次任务开始时 Agent 都会先读到它：

| 文件 | 用途 |
| --- | --- |
| `AGENTS.md` | 多种编码 Agent 通用的约定文件，写给所有 Agent 看 |
| `.bit-agent/instructions.md` | 只写给 Bit Agent 看的补充说明 |

两个都有时按上表顺序都读。适合写的内容：用哪个包管理器、测试和构建命令、代码风格、哪些目录不要碰、提交前要做什么。

- 合计最多读取 16 KB（约 4000～5000 tokens），超出部分截断，并提示 Agent 需要时自己读原文件。
- 内容以“项目说明”的身份交给主 Agent：它**不能放宽本轮权限**（例如不能让“逐次确认”变成自动批准），与你本次的要求冲突时以你的要求为准。
- 每轮任务重新读取，改了文件下一轮就生效。执行记录里会显示“已读取项目说明 AGENTS.md”。
- 调查子 Agent 和独立验收 Agent 不读取这些文件。

## 验证命令

`.bit-agent/verify.json` 指定修改后怎样验证，例如 Go、Rust 项目的测试命令，或者哪些文件不需要验证。格式和规则见 [修改后的验证](VERIFICATION.md)。Agent 修改 `.bit-agent/` 下的任何文件都必须由你逐次确认。

## 提交到 Git

任务结束后，在“审阅改动”里可以把这次任务改过的文件提交到 Git：

1. 面板列出这次任务改过、还没撤销、并且相对当前提交确实有变化的文件。
2. 填写提交信息，或点“生成提交信息”让当前模型根据任务目标和差异起草（模型不可用时用任务目标做草稿）。
3. 可以勾选“提交到新分支”，默认分支名是 `bit-agent/task-<任务编号前 8 位>`。
4. 点“提交 N 个文件”。

规则：

- **只提交这次任务的文件。** 你自己改的其他文件、自己暂存的其他改动都保持原样（使用 `git commit --only`）。
- 任务结束、并且同一目录没有其他任务在执行时才能提交。
- 优先使用你自己安装的 Git，这样你的用户名、邮箱和提交钩子都照常生效；找不到时才用便携版附带的 Git（它不能运行需要 `sh` 的钩子）。
- 提交钩子失败、没有配置用户名和邮箱等错误会原样显示出来，不会绕过（不使用 `--no-verify`）。
- 不会推送到远程仓库。

## 管理对话

左侧会话列表上方的搜索框可以按标题、任何一轮的要求和回答搜索对话。把鼠标移到某个对话上会出现两个按钮：

- **重命名**：直接在列表里改名，回车保存，Esc 放弃。
- **删除**：删除这段对话的全部记录（各轮要求、回答、执行事件）和改动快照，无法恢复。项目里的文件、已经提交的 Git 记录和长期记忆不受影响。正在执行的对话需要先停止才能删除。

## 对应代码

| 文件 | 作用 |

| `runtime/infrastructure/project_instructions.py` | 读取说明文件 |

| `runtime/application/service.py` | `git_status`、`suggest_commit_message`、`commit_changes` |
| `apps/desktop/src/renderer/git-commit-panel.ts` | 审阅弹窗里的提交面板 |

表中 Python 路径都位于 `services/agent/src/bit_agent/`。
