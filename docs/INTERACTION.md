# 运行途中暂停、调整要求和回答问题

> 本轮交互已补充测试和真实桌面验收。权限与资源边界见 [功能说明](PRODUCT_HARDENING.md)。

## 界面怎么用

1. 任务执行时，点击“暂停”。
2. “正在暂停”表示当前模型或工具调用还没有结束。出现“已暂停”后，才是安全的修改时机。
3. 选择“补充要求”或“修改目标”，填写内容，点击“提交要求并继续”。
4. 不需要修改时，点击“不修改，继续执行”。
5. 想结束这轮任务时，仍然使用原来的“停止”，它表示取消，不是暂停。

| 操作 | 对原任务的影响 |
| --- | --- |
| 补充要求 | 保留原目标，增加新的约束，原执行计划需要重新考虑 |
| 修改目标 | 替换工作记忆中的目标，清除原目标的约束和待执行计划 |
| 继续执行 | 不增加新要求，从安全位置接着走 |
| 停止 | 取消本轮执行，保留已保存的记录，之后可以继续同一对话 |

例如原目标是“做一个登录页面”：

- 补充“支持深色主题”：目标仍是登录页面，增加主题要求。
- 修改为“先别做页面，帮我分析登录接口”：旧的页面计划不再继续执行。
- 已经写入磁盘的页面文件不会因此自动删除或回滚。

修改要求时，尚未执行的旧工具申请会被标记为跳过，模型需要根据新要求重新规划。已经执行过的修改、测试状态和错误不会清空，否则会误以为代码从来没有变过。

## Agent 中途提问

主 Agent 增加了一个 ask_user 工具。它可以提出一个问题、2 到 3 个选项，并标出推荐项和理由。

界面会显示问题卡片，你可以选择一个选项，也可以填写自己的回答。

普通低风险问题默认等待 60 秒；每个问题允许设置 10 到 600 秒。没有回复时，后端采用推荐项继续执行，并记录来源为“超时默认”，而不是“用户回答”。

这里的推荐项只是模型认为更合适的选择，不保证是绝对最优。

涉及删除、覆盖、付费、隐私或权限的提问，模型必须标记 requires_confirmation。这类问题不设置自动通过的截止时间，必须等你回答、修改要求或取消任务。问答中的风险标记由模型给出，但真正写文件或运行代码另有框架权限关卡。问答返回值不能绕过该关卡；框架发起的权限确认绝不超时批准。

收到问题时，也可以直接提交新的任务要求。旧问题会失效，Agent 按新要求重新规划。迟到的回答不能应用到下一道问题。

同一批模型输出中，如果既提出问题又申请其他工具，框架会先跳过那些工具。必须拿到回答后重新调用模型，不能没等回答就执行预设操作。

## 时间和资源边界

暂停或等待回答的时间不计入任务执行超时。任务继续后，使用剩余的执行时间，不是重新获得完整的一小时。

暂停属于“在安全位置等待”，不是强制冻结：

- 正在进行的模型请求会先返回。
- 正在运行的工具会先结束，不会为了暂停而把一次文件写入截断。
- 正在进行的子 Agent 调查会先返回主 Agent。
- 暂停期间保留工作区写入锁，避免其他任务同时改同一个目录；全局执行名额会归还。
- 默认执行名额是 2。两个任务都在等人时，其他工作区仍能执行；恢复时重新取得名额。

用户也可以取消等待，不必一直保持暂停。

## 保存在哪里

沿用本地 SQLite，不增加 Redis 或其他数据库服务。

- 任务状态和当前问题保存在任务记录中。
- 补充要求与修改目标保存在 intent_updates 中。
- 用户回答和超时默认的来源会写入事件记录，并随工具结果进入对话历史。
- 已应用的要求会同步更新 Working Memory 和压缩摘要中的目标、约束与计划。
- 用户要求先保存，再交给执行循环处理。下次续聊时，会找回已提交但尚未应用的要求。

程序关闭或异常中断后，正在暂停、等待回答的任务会被标记为中断。记录不会删除，但不能恢复原来的 Python 等待现场。用户需要在同一对话继续；系统不会偷偷重跑旧工具，也不会在重新打开后自动选择旧问题的推荐项。

## 代码怎么分工

| 文件 | 作用 |
| --- | --- |
| services/agent/src/bit_agent/runtime/application/interaction.py | 管理暂停、继续、问题、回答和超时；决定是否还可以接收本轮输入 |
| services/agent/src/bit_agent/runtime/application/service.py | 给每个任务接入交互控制，处理对外请求和任务超时 |
| services/agent/src/bit_agent/runtime/infrastructure/storage.py | 保存交互记录，恢复未应用的要求，处理程序中断 |
| services/agent/src/bit_agent/runtime/application/delegation.py | 把 ask_user 暴露给主 Agent；调查子 Agent 没有该工具 |
| services/agent/src/bit_agent/agent/runtime.py | 在安全位置接收要求，更新记忆与摘要，跳过过时工具计划 |
| apps/gateway/src/transport/http/app.ts | 提供任务交互 HTTP 接口 |
| apps/gateway/src/infrastructure/runtime/local-task-store.ts | 把交互请求传给本机 Python |
| apps/desktop/src/main/transport/electron.ts | 桌面 IPC 通过 GatewayClientPort 发送请求 |
| apps/desktop/src/main/transport/preload.cts | 给页面暴露受控的交互方法 |
| apps/desktop/src/renderer/interaction-view.ts | 暂停按钮、意图编辑器、问题卡片和倒计时 |
| apps/desktop/src/renderer/main.ts | 将交互界面与当前会话、实时事件连接起来 |

整体顺序：

```text
点击暂停 / 提交要求 / 回答问题
  -> Electron 页面
  -> preload 与主进程
  -> Gateway
  -> 本机 AgentRuntime
  -> 记录写入 SQLite
  -> Agent 在安全位置接收
  -> 更新上下文和工作记忆
  -> 继续模型与工具循环
```

## 接口

统一入口：POST /v1/tasks/:taskId/interaction。

```json
{"action":"pause"}
```

```json
{"action":"resume"}
```

```json
{"action":"supplement","text":"保留原功能，增加深色主题"}
```

```json
{"action":"replace","text":"先停止做页面，改成分析登录接口"}
```

```json
{"action":"answer","question_id":"界面收到的问题编号","option_id":"选项编号"}
```

自由回答使用 text 代替 option_id。问题编号必须匹配当前问题；两种回答方式不能同时提交。

这些接口只接在默认的 local 运行方式上，旧 Redis Worker 路径没有新增这套交互能力。

## 下一步验收重点

本轮没有执行以下检查，需要另行验收：

1. 暂停发生在模型请求、工具执行和任务收尾三个边界时，状态是否正确。
2. 补充与替换目标之后，旧工具计划不继续执行，旧摘要也不覆盖新要求。
3. 回答、超时与取消同时发生时，只采用一个最终结果。
4. 需要明确确认的问题不能超时自动批准。
5. 页面切换、刷新以及进程重启后，问题和新要求不会串到其他对话。
6. 原有 Docker 验证、上下文压缩和多 Agent 能力没有回归。
