## 最终 exe 实际操作

验收脚本直接启动最终目录中的 `Bit Agent.exe`，不是启动源码版 Electron 后声称已经验证打包程序。

1. 子进程 PATH 移除开发机上的 Python、Node、Git 等路径，只保留 Windows 系统路径；应用自行加入随包工具目录。
2. 使用新的用户配置和 SQLite 目录，不读写日常会话。
3. 页面能够初始化，自动启动 Gateway 和 Python，无需另开数据库服务。
4. 未提供进程令牌的 Gateway 请求被拒绝。
5. 通过桌面设置接口配置本机假模型；磁盘设置不包含明文测试密钥，页面接口也不返回密钥。
6. 模型最终完成前，页面已经显示真实收到的文字片段。
7. 正常关闭应用，重新启动，恢复原会话和加密设置，并成功续聊。模型收到前一轮内容。
8. 执行中点击暂停，在安全位置修改目标，再继续执行。
9. 请求写入测试文件时，界面先出现框架授权卡片。明确批准前文件不存在。
10. 批准后真实补丁工具写入文件，再出现中途提问卡片。
11. 等待回答期间取消任务，任务结束后打开改动审阅，显示真实前后差异。
12. 通过界面撤销本次新增文件，文件回到不存在的状态。

另外，Python 用例覆盖了只读拒绝写入、等待期间用户改文件导致补丁被拒绝、撤销拒绝覆盖后续编辑、暂停释放名额、取消不泄漏名额、普通问题超时默认、需要确认的问题不自动通过、旧回答失效，以及符号链接不能绕过秘密文件保护。

## 验收期间修复的实际问题

- 测试失败时不能误清除“仍需验证”的状态，即便工具没有返回完整文件列表。
- 取消时要清理测试容器，并给后台进程留出保存状态和清理的时间。
- 权限确认显示完整操作，不能只展示截断片段。
- 页面操作详情不能使用被现有 CSP 禁止的内联样式，没有放宽安全策略。
- 未执行验证的普通聊天显示“未运行”，不是“未通过”；统一质量检查标题不再写死 Ruff。
- 流式文本切换会话后重新播放时不能重复追加旧内容。
- 损坏的模型设置和不可解密的旧密钥不能阻止用户填写新设置。
- 验收脚本必须等待“完成且按钮恢复”后再发送下一轮，不能仅凭状态文字就提前点击。

## 仍需明确的限制

- 没有调用真实付费模型，无法据此承诺某个第三方接口兼容、响应质量或网络稳定性。
- Docker 是隔离验证的外部前提，本轮没有把它打进 exe，也没有绕过隔离限制去执行用户项目。
- 前端自动验证目前支持 npm / 指定版本 pnpm 的单包项目；不重放锁文件，不执行安装脚本。多包工作区、私有包和本地依赖不属于已支持范围。
- 发布物没有代码签名，不是经过签名的安装程序，也没有实现自动更新。
- 崩溃恢复保留历史和已提交要求，不等于从任意一条机器指令继续执行。缺少完成快照的改动不自动撤销。
- 多文件撤销不是跨外部编辑器的原子事务。检测到内容变化会拒绝覆盖，操作时仍应避免同时在别处编辑相同文件。
